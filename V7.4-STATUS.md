**Known gaps (not fixed, not hidden)**
1. SECURITY LIMIT: Protection scans after a file is written. A double-click one second after a threat arrives can still open it (the harmless virus file is quarantined about 18 s later). Real fix = blocking at open time (fanotify) in the planned Protection rewrite.
2. Protection runs under your own account: a program can still block it for up to 5 s before the guard notices. Real fix = run it as a separate system service.
3. A restored file's content stays allowed by design: an identical copy of a restored file is never flagged again.
4. The low-disk warning uses KDE's standard wording and buttons (cannot be changed without patching KDE): no "open Settings > Storage" button.
5. VS Code crashed once in 4 full runs (run 44717308274; bus error, probably the disk-full test with VS Code open). Not seen again after VS Code was closed before that test.
6. Not tested at all: extracting a zip through the File Explorer screen (only by command), real sleep and wake, App Store and Back up my files beyond opening, Secure Boot / NVIDIA / real-disk encryption, how animations feel.

Small visual issues from QA still open: threat notice covering the Quarantine/Delete buttons; keyboard name "Bulgarian (new phonetic)" vs "Bulgarian (Phonetic)"; File Explorer search heading breaking mid-word; Run dialog buttons flush with the edge; Task Manager Services showing raw unit names; Task Manager Apps empty in 3 screenshots (unverified); "allowed files" list on the Protection page with undo (not built).
