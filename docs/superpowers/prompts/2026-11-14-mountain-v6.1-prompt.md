## Standing rules (all versions)

**Quality**
- "Nothing less than perfect." Every feature gets an image check (`tests/check-image.sh`) and a vm-test check with a screenshot.
- Fix root causes. Never retry a flaky check away, and never weaken old image checks.
- **Check locally before pushing:**
  - `bash -n` and shellcheck on changed scripts
  - qmllint or a QML load test on changed QML
  - XML and desktop-file validation
  - the `tests/test-*.sh` self-tests
- Push only when those are clean. Reproduce VM-only problems with a short targeted run before a full one.
- **UI gaps are not cosmetic.** Fix them before merging; only truly trivial ones may be listed instead.
- **Reviews:**
  - a code review per task
  - a final whole-branch review on the most capable model
  - a walk-through on the main image after the merge

**Working style**
- **Lead plus helpers.** The lead plans, dispatches subagents and decides.
  - Use one helper per failing check or area, each on its own files, in parallel.
  - Mechanical work goes to the cheapest model that can do it; mid-tier for fixes; the most capable for research, UI design and unexplained failures.
- **Keep tokens low:**
  - ponytail full
  - read only failed log lines
  - one background `gh run watch` per run, no polling
  - one build per fix wave
- **Don't sit idle during VM runs.** Re-audit the fix wave, check audit coverage and run static checks. Commit locally, but don't push while a run is going.
- **Commit and push after every fix wave,** so stopping at any moment loses nothing.

**Owner communication**
- The owner is not a programmer. Use short plain lines, status tables and a live task list.

**Security and build**
- **Never commit:**
  - secrets or `cosign.key`
  - owner photos
  - VM disks or ISOs
  - `.superpowers/`, which is not ours
- Commit only files you changed, with explicit paths.
- **Try Mountain:**
  - Never print the browser password (GitHub secret `TRY_PASSWORD`).
  - Never type passwords in the browser.
  - Relaxations for the Try VM (password 123, passwordless admin) live only in `try-mountain.yml`.
- **Builds:**
  - No third-party build-time downloads beyond Fedora repos, repos already in the recipe, Flathub, or vendored GPL/MIT code.
  - No background updates.
- **Gaming and branding:**
  - Security changes must not break gaming; anything risky is opt-in.
  - Never copy brand logos.
  - No literal "Mountain" in `/usr/share/applications` or `/etc/xdg`.
- **Editing and Git:**
  - Edit YAML with Python exact-string replacement that asserts exactly one match. The checkout is CRLF.
  - Never stash, reset or switch branches in the shared `mountain` folder; use a worktree.
- End commit messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. PR bodies end with the Claude Code line.
